# 主程序非阻塞启动设计

## 问题

主程序在创建和呈现 WebView 前同步验证高德 Key，并重新生成所有活动台风的 Widget 地图缓存。该过程涉及网络请求及多张 708×708 图片合成，会让用户点击主程序后长时间看不到窗口。

## 方案

- WebView 的创建、消息桥注册、本地页面加载和呈现保持原流程。
- 启动时只同步读取已保存 Key 和本地配置状态，不等待远程 Key 验证或 Widget 地图生成。
- 已保存 Key 的验证与缓存刷新作为不等待的后台异步任务启动。
- 后台验证完成后更新 `amapRuntimeState`，供“更多→高德Key”面板读取；有效则刷新缓存，无效则记录具体错误。
- 保留用户主动保存 Key 时现有的异步验证与缓存刷新流程。

## 边界与错误处理

- 后台任务错误仅记录日志和状态，不阻止地图主页面打开。
- 不修改高德 Key 存储、地图缓存格式、WebView 生命周期或 Widget 布局。
- 页面关闭后后台任务允许随脚本生命周期结束；旧缓存继续可用。

## 验收

1. 启动过程中先执行 `webView.present`，不再等待 `verifyAmapKey` 或 `refreshWidgetMapCache`。
2. 主程序地图可打开。
3. 已保存 Key 仍会在后台验证，并在有效时刷新 Widget 地图。
4. 全项目 TypeScript 诊断无错误。
