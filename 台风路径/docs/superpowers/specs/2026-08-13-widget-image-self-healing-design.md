# 小组件图片自动刷新与缓存一致性修复设计

日期：2026-08-13
状态：用户已批准方案 A

## 目标

解决大号小组件经常停留在“地图缓存生成中”或图片长期不更新的问题。数据更新后，小组件应能自行生成当前选中台风的地图；失败时继续显示上一份完整缓存，而不是主动丢弃可用图片。

## 已确认根因

1. Widget 会刷新 `state.json`，但地图只能由主程序生成；数据末点推进后，严格时间匹配立即使旧图失效。
2. 主程序地图刷新是未等待任务，WebView 关闭或 `run_single` 重启会中断生成。
3. `replaceFileSync` 错误声明为 `async` 且调用未等待，文件重命名失败可能被误判为成功。
4. 高德静态图下载没有有限超时，串行批次可能长期卡在某一张。
5. 固定 PNG 文件名与独立 manifest 更新存在错代窗口。

## 方案

### 1. Widget 自愈

- 大号 Widget 完成实时数据加载后，计算当前台风地图内容 revision。
- 如果当前 revision 的图片不存在且已配置有效 Key，直接在 Widget 执行上下文中只生成当前选中台风的一张图，然后再 `Widget.present`。
- 生成失败时读取最近一份完整的历史 manifest 与图片，继续展示旧图，并标记缓存数据/地图更新中。
- 中号 Widget 保持纯数据模式，不生成图片。

### 2. 不可变代次缓存

- 图片改为 `map-<id>-<revision>.png`。
- manifest 改为 `map-<id>-<revision>.json`，保存 revision、图片文件名和生成时对应的台风快照。
- 先写完整 PNG，再提交 manifest；manifest 是完整代次的证明。
- Widget 只读取 manifest 指向的同代 PNG，不再重新拼固定路径。
- 每个台风保留当前与上一份完整代次，清理更老文件，防止长期累积。
- 兼容读取旧版 `map-<id>.json/png`，用于首次升级时的降级显示。

### 3. 内容 revision

revision 由真实影响地图的输入稳定计算：台风编号、参与绘制的实况路径、最新有效点、风圈与预报路径。不会使用每次请求都变化的本地 `updatedAt`，避免数据未变却反复生成。

### 4. 主程序预生成

- 主程序继续后台预生成全部活动台风地图，但当前选中台风优先。
- 已有匹配 revision 的完整缓存直接跳过。
- 每成功发布一张即可通知 Widget reload，不必等待整批。
- 高德底图下载增加有限超时；单台失败不阻塞后续台风。

### 5. 错误与安全

- 修正同步文件替换函数的浮空 Promise。
- 图片生成失败不删除上一份完整缓存。
- Key 仍只在原生/Widget App Group 范围读取，不写入源码、manifest、日志或图片。
- 不新增网络域名、权限或依赖。

## 验收标准

1. 最新数据与旧 manifest 不匹配时，大号 Widget 能自行生成当前台风地图。
2. 自愈失败时仍能显示上一份可解码图片，不出现无必要空白。
3. manifest 的 revision、mapPath 与 PNG 一致；不存在“manifest 成功但 PNG 缺失”的假成功。
4. 相同地图输入不会重复生成；输入变化时 revision 必须变化。
5. 高德单图请求在有限时间内结算，单台失败不阻塞其余台风。
6. TypeScript 诊断为 0；medium/large Widget 预览成功；主程序可正常打开。

## 非目标

- 不修改主地图 WebView 的布局、图层或交互。
- 不改变 Widget 的整体视觉设计和 30 分钟目标刷新策略。
- 不在 Widget 内恢复高风险的多瓦片并发拼接。
